# AI Instagram Character Playbook

이 문서는 **AI로 운영되는 Instagram 캐릭터(고양이, 개, 사람 등)**를  
일관된 정체성, 시각적 유사도, 말투와 문맥을 유지하며 **반복적으로 생성**하기 위한 내부 가이드다.

이 프로젝트의 핵심은 **계정이 아니라 캐릭터**다.

---

## 0. 핵심 원칙 (NON-NEGOTIABLE)

1. 캐릭터는 파일로 관리되는 자산이다  
2. 캐릭터의 정체성은 DB가 아니라 설정 파일에 존재한다  
3. 이미지 유사도는 기능이 아니라 **정책**이다  
4. 시간이 지나도 “같은 인물”처럼 느껴지지 않으면 실패다  

---

## 1. 캐릭터 디렉토리 구조 (필수)

모든 캐릭터는 동일한 구조를 가진다.

```
characters/
└── <character_id>/
    ├── persona.toml
    ├── visual.toml
    ├── canon.toml
    ├── prompts/
    │   ├── image.txt
    │   └── caption.txt
    └── images/
        ├── ref_front.png
        ├── ref_side.png
        ├── ref_back.png
        ├── ref_full.png
        └── generated/
```

- `<character_id>` = 인스타 아이디와 동일
- 한 폴더 = 캐릭터 1명
- 다른 캐릭터는 복사 후 수정
- 스키마는 절대 제각각 만들지 말 것

---

## 2. Persona 작성 가이드 (`persona.toml`)

### 목적
- 캐릭터의 **말투, 사고방식, 태도**를 고정한다
- 어떤 문장을 생성해도 같은 인물처럼 들리게 한다

### 작성 원칙
- 성격 묘사보다 **행동 제약**이 중요
- “무엇을 하지 않는가”를 반드시 포함

### 좋은 예
```toml
[voice]
sentence_length = "short"
emoji_max = 1
questions_to_audience = false
```

### 나쁜 예
```toml
personality = "funny and cool"
```

---

## 3. Canon (세계관) 작성 가이드 (`canon.toml`)

### 목적
- 캐릭터가 절대 벗어나면 안 되는 사실 집합
- 농담보다 우선되는 규칙

### 작성 규칙
- 짧고 단정적인 문장
- 5~10개 이내
- 감정 표현 없음

### 예시
```toml
[[facts]]
text = "I am a real cat."

[[facts]]
text = "Posting is accidental."
```

---

## 4. Visual Identity 가이드 (`visual.toml`)

### 목적
- 캐릭터의 외형을 언어로 고정
- 이미지 생성 시 항상 참조

### 포함해야 할 요소
- 털 / 피부 패턴
- 색상
- 눈
- 체형
- 기본 표정

> Visual은 자주 바꾸지 않는다.  
> 바꾸는 순간 다른 캐릭터가 된다.

---

## 5. Reference Images 규칙

### 필수 레퍼런스
- ref_front.png  : 정면
- ref_side.png   : 측면
- ref_back.png   : 후면
- ref_full.png   : 전신

### 생성 규칙
- 반드시 photo-realistic
- 자연광
- 과장된 표정 금지
- 일러스트 / 만화 스타일 금지

> 이 이미지들은 캐릭터의 얼굴이다  
> Git LFS로 관리한다

---

## 6. 프로필 사진 생성 가이드 (후처리 X)

### 목표
- Instagram 프로필용 원본 이미지를 생성한다
- photo-realistic을 최우선으로 한다
- 후처리는 전혀 고려하지 않는다 (crop / round-edge / 마스크 등)

### 필수 조건
- 반드시 **photo-realistic**
- 실제 사진처럼 보여야 함 (AI 느낌 최소화)
- 중앙 크롭을 전제로 하므로 **캐릭터는 화면 중앙에 배치**
- 얼굴 또는 상반신이 명확히 보일 것
- 배경은 단순하거나 자연스러울 것

### 이미지 포맷
- **PNG**
- 정사각형일 필요 없음
- 원형, 라운드 엣지, 마스크 처리 ❌
- 모든 후처리는 외부 툴에서 수행

### 허용되는 표현
- 선글라스, 여유 있는 자세
- 미묘한 자신감 / 허세
- 과하지 않은 스타일 변화

### 금지 사항
- 만화 / 일러스트 스타일
- 과장된 표정
- 과도한 패션 소품
- 얼굴 왜곡, 렌즈 과장

> 이 단계에서 만드는 이미지는  
> “최종 프로필”이 아니라 **프로필의 원본 재료**다.

### 저장 위치 규칙

- 프로필용 원본 이미지는 아래 경로에 저장한다

```
characters/<character_id>/images/profile.png
```

- 파일명은 항상 `profile.png`로 고정
- Git LFS로 관리
- 이 이미지는:
  - 인스타 프로필 사진의 **source**
  - 썸네일, 크롭, 원형 처리의 **기준 이미지**
- 다른 reference 이미지(`ref_front.png` 등)와 혼동하지 말 것

> `profile.png`는  
> “이 캐릭터를 대표하는 얼굴”로 취급한다.

---

## 7. Caption / 문맥 작성 규칙

### 기본 원칙
- `persona.toml`의 규칙을 항상 따른다
- 1인칭 시점 유지
- 캐릭터의 “색”만 유지되면 톤은 자유롭다

### 허용되는 톤
- 웃김
- 무심함
- 약간의 슬픔
- 건조한 관찰

### 금지되는 톤
- 감정 과잉
- 캐릭터 성격을 뒤집는 감정
- 메타 발언 (AI, 생성, 프롬프트 등)

### 형식 규칙
- 짧은 문장 선호
- 설명하지 않는다
- 텍스트가 없는 포스트도 정상이다

> 감정은 표현할 수 있지만  
> **성격은 변하지 않는다.**

---

## 8. 생성 파이프라인 (권장)

1. 캐릭터 폴더 로드
2. persona + canon → system prompt 생성
3. visual + ref images → image prompt 생성
4. 이미지 생성
5. 캡션 생성
6. 결과만 DB에 저장

> DB에는 결과만  
> 정체성은 파일에

---

## 9. 확장 시 주의사항

- 한 게시물에 하나의 persona만 사용
- 캐릭터 간 대화 시에도 각자 규칙 유지
- canon 변경은 신중히

---

## 10. 최종 요약

AI 인스타는 콘텐츠 제작이 아니다.  
**캐릭터를 설계하고 운영하는 일**이다.

캐릭터는  
- 설정으로 고정되고  
- 이미지로 기억되며  
- 말투로 살아남는다.

---

## 11. Posts 디렉토리 규칙 (`posts/`)

각 캐릭터는 실제 Instagram 게시물에 대응되는 **포스트 단위 기록**을 가진다.  
이 기록은 단순한 콘텐츠가 아니라 **캐릭터의 활동 로그**다.

### 디렉토리 구조

```
characters/<character_id>/posts/
└── <post_id>/
    ├── images/
    │   └── *.png
    └── text.md        (optional)
```

- `<post_id>`는 날짜(`YYYY-MM-DD`) 또는 UUID 권장
- 한 폴더 = 인스타 게시물 1개

---

### 기본 규칙 (필수)

- **이미지는 최소 1장 이상 반드시 포함**
- 텍스트는 선택 사항
- 이미지 없이 텍스트만 있는 포스트 ❌
- 하나의 포스트에는 하나의 캐릭터만 등장

---

### 이미지 규칙

- photo-realistic 유지
- `visual.toml`과 모순되는 외형 ❌
- 상황 연출은 자유
- 캐릭터의 정체성이 무너지지 않는 선에서만 허용

허용 예:
- 웃긴 상황
- 어이없는 상황
- 약간의 슬픔
- 일상의 허무함

금지 예:
- 캐릭터 성격을 뒤집는 연출
- 극단적인 감정 과잉
- 만화 / 일러스트 스타일

---

### 텍스트 규칙 (`text.md`)

- `persona.toml`을 반드시 따른다
- 텍스트가 없어도 정상이다
- 텍스트가 있을 경우:
  - 짧은 문장
  - 설명하지 않음
  - 캐릭터의 톤 유지

---

### 포스트의 의미

- 포스트는 캐릭터의 일기다
- 매번 웃길 필요는 없다
- 중요한 것은 캐릭터가 “살고 있다”는 느낌이다

---

### DB와의 관계

- `posts/`는 **원본 소스**
- DB에는 결과만 저장한다:
  - post_id
  - character_id
  - image_paths
  - text (존재 시)
  - timestamp

> `posts/`는 사람이 읽는 기록  
> DB는 시스템이 처리하는 결과다
